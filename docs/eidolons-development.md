# Eidolons development setup

The project uses Eidolons CLI 4.6.2, the full default roster (ATLAS, RAMZA,
Vivi, IDG, FORGE, VIGIL, Kupo, Gilgamesh), and the optional SPECTRA/APIVR-Δ
methods. Claude Code, Copilot, and Codex adapters are generated by the CLI.
Resolved member versions and integrity receipts live in `eidolons.lock`.

## Bootstrap before opening a coding-host session

Generated host adapters reference `.eidolons/` packages and hook shims. These
runtime files and the generated root `EIDOLONS.md` are ignored by Git; EIIS v3
forbids shipping a root cortex in a member package. A fresh checkout must install them before
using the adapters. All tooling runs inside the development container:

```sh
docker compose build
docker compose -f docker-compose.yml -f docker-compose.eidolons.yml build
docker compose -f docker-compose.yml -f docker-compose.eidolons.yml run --rm crystalium eidolons sync --non-interactive
docker compose -f docker-compose.yml -f docker-compose.eidolons.yml run --rm crystalium eidolons harness install --non-interactive
docker compose -f docker-compose.yml -f docker-compose.eidolons.yml run --rm crystalium eidolons verify
docker compose -f docker-compose.yml -f docker-compose.eidolons.yml run --rm crystalium eidolons harness check
```

Reopen the host session after installation. The optional tooling image preserves
the normal service's source mount and unprivileged user. It does not modify the
published CRYSTALIUM runtime image. CLI caches in a one-off container are
disposable; installed project packages remain in the bind-mounted `.eidolons/`.
To upgrade the CLI, update `EIDOLONS_REF` in `Dockerfile.eidolons`, rebuild, and
review `eidolons upgrade --check --project` before updating member constraints.
Commit the manifest, lockfile, and generated adapters together. Keep
`.claude/settings.local.json` private to the local checkout.

## Validation boundaries

The 4.6.2 refresh verified all ten member releases and passed `harness check`.
`doctor` also inspects host MCP deployments: the inherited atlas-aci/Junction
lock entries refer to host paths and an older Junction executable that are not
available inside this container. Those runtime diagnostics do not establish
member-installation failure; repair or upgrade these optional MCP deployments
separately in their owning host environment. Copilot model wiring is unsupported
upstream, and its session-start context adapter has an upstream delivery caveat.
Harness wiring checks do not prove live delegation or strict enforcement.
